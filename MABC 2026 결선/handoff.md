## 2. 현재 결정/정리된 방향

- 서비스 MVP 중심은 **업무 재개 카드 생성** 그대로 유지
- 기록 접근: 사용자가 전부 붙여넣는 방식보다, 연결된 도구·MCP로 관련 업무 자료를 찾는 걸 중심으로 두되, 연결이 없으면 사용자 제공 텍스트/요약/키워드 기반으로 동작
- 외부 데이터 활용 시 저작권·출처 표기 준수, 타인 저작물·동의 없는 개인정보 포함 금지
- 태그/키워드는 선택 옵션
- 내부 대화/기록 참고는 외부 기록 없을 때 보조 수단으로만, 실제 환경 확인 필요
- 문제 정의 방향: 복귀·전환·토스·인수인계 상황에서 흩어진 기록을 다시 훑지 않으면 다음 행동을 못 잡는 불편
- MVP 표시 상한: 다중 업무일 때 한 번에 보여주는 카드 수에 상한을 두고 나머지는 요약·목록으로 안내하는 방향
- 다중 업무 처리: 재개 맥락과 관련도 높은 업무 우선, 애매하면 무리하게 쪼개지 않고 요약·통합 안내 가능
- 플레이리스트/업무 개시 UX 힌트: "무엇을 꼭 완벽하게 재개할 필요 없이, 5분만 이어서 보기" 같은 진입 문구를 필요한 곳에 얇게 사용 가능

## 3. 스킬 테스트에서 확인된 보완점 (다음 작업 대상)

### 3-1. 완료 판정 보정 (가장 우선)
- "끝났다", "다 했", "더 할 일 없음"처럼 확정적 종료 표현만 완료로 보기
- "거의 끝남", "마무리 예정", "다음 주에 마무리 예정", "추가 보완 필요" 등은 완료로 단정하지 말고 진행 중 또는 확인 필요(기록 충돌 시)로 두기

### 3-2. 충돌 시 상태 판정 보정
- 충돌 감지는 주의사항에만 들어가지 말고 상태 판정에도 반영
- 충돌이 있으면 상태는 "확인 필요(기록 충돌)"으로
- 첫 행동은 "충돌 해소 후 재개" 방향
- 충돌 내용은 주의사항에 표시

### 3-3. 다중 업무 처리 원칙
- 여러 업무가 보이면 업무별로 나누어 각각 카드 생성
- 다만 카드가 지나치게 많아지지 않도록 상한 적용
- 재개 맥락과 관련도 높은 업무 우선, 나머지는 요약·목록 안내
- 업무 구분이 애매하면 무리하게 쪼개지 말고 요약/통합 안내 가능

### 3-4. 업무명 추출 + 근거 표현 보정
- 프로젝트명/업무명을 맥락에서 더 잘 잡아내도록 보강
- 근거는 맥락 있는 범위에서만 쓰고, 없는 정보는 과추정하지 않기
- 예: 기록이 없는데 "충돌/불명확" 표현을 넣거나, 맥락에 없는 "어제" 같은 표현을 근거로 쓰는 것 완화

### 3-5. 단순/복합 판단 보정
- 대기 항목이 있으면 복합으로 보거나 최소 복합 처리가 필요한 상태로 보기
- 단순 할 일은 진짜 단순할 때만 간소화

## 4. 우선순위 (다음 작업 추천 순서)

1. **완료 판정 보정** — 확정 표현만 완료로
2. **충돌 시 상태 판정 연결** — 충돌 있으면 확인 필요(기록 충돌)
3. **다중 업무 처리 원칙** — 상한/요약/우선순위, 과도 노출 방지
4. **업무명 추출·근거 과추정 완화**
5. **단순/복합 판단 보정** — 대기 있으면 복합 경향
6. **다시 스킬 테스트**로 결과 확인
7. **MVP 구성으로 넘어가기** — 첫 화면/입력/출력/범위 확정

## 5. MVP 구성으로 넘어가기 전 정리해둘 것

- MVP 중심: 업무 재개 카드 생성
- 입력 방식: 프로젝트명/업무명, 최근 한 줄 메모, 붙여넣은 기록, 키워드/태그
- 연결/연동 가정: 서비스 환경에 연결된 도구·MCP로 관련 업무 자료 찾기(해당 연동 가능한 경우)
- 태그/키워드: 선택 옵션
- 다중 업무: 업무별 카드 여러 장, 단 상한 적용 후 나머지는 요약·목록
- 진입 안내: “완벽하게 재개할 필요 없이, 5분만 이어서 보기” 느낌을 얇게 넣을 수 있음
- MVP 범위에서 뺄 것(당장은 아님): 저장소 자동 연동 전체, 히스토리 누적 관리, 토스·인계용 별도 포맷, 교대·인수인계 템플릿
