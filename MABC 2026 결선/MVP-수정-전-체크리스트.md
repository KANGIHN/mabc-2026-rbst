## 5. 데모 라우팅 설계 (확정)

### 방식: 하이브리드
1. **데모 칩(버튼) 클릭** → 해당 사건의 질문/사건번호로 입력 채우고 runGenerate(isDemo=true)
2. **입력창에 데모용 사건번호 포함** → 해당 사건으로 자동 라우팅 (isDemo=true 처리)
3. **미일치 입력** → 안내 메시지 + 데모 칩 재유도 (빈 화면 방지)

### 데모용 사건번호 목록 (예시)
- 2026가단12345 (손해배상, 충돌)
- 2026가단67890 (임대차보증금, 통합)
- 2026나54321 (공사대금 항소, 우선순위)

### 구현 위치
- 프론트: demo-pick-btn onclick 핸들러, genBtn onclick 핸들러(사건번호 감지)
- 백엔드: buildDemoResult에서 사건번호 포함 쿼리 매핑 또는 별도 데모 매핑

## 7. 카드 헤더 변경 (D-n 표시)

### 변경 전
```
[업무명]                    [종류 태그] [상태 태그]
```

### 변경 후
```
사건번호: 2026가단12345
사건명: 손해배상 청구
다음 기일: 9/22 (D-7)
[상태 태그]
```

### D-n 계산
- 현재 날짜 기준 다음 기일까지 남은 일수
- 프론트에서 계산하거나 백엔드 응답에 포함
- 기일이 지난 경우 "기일 지남" 또는 D+ 표현 고려
