## 2. 촬영 장면 구성 (권장 흐름, 총 3분 이내)

### 장면 1: 서비스 첫 화면 (약 15초)
**목표**: 서비스 목적 + 상태 표시 확인

1. 브라우저에서 https://mabc-2026-rbst.vercel.app 접속
2. 첫 화면 구성 소개:
   - 헤더: "ResumeCard — 이어가고 싶은 일 하나만 알려주면..."
   - "실제 기록 연동" 상태 배너 (녹색): Google Calendar·Gmail·Drive 연결 환경 안내
   - 데모 예시 버튼 3개 (MBCD 프로젝트, MABC 2026 결선 준비, 프로젝트 전환 정리)
   - 입력창 + 카드 생성/데모 예시로 체험하기 버튼

**나레이션/자막 예시**:
> "이 서비스는 이어가고 싶은 일 하나만 알려주면, 흩어진 기록을 다시 훑지 않고도 업무 재개 카드를 바로 보여줘요.
> 현재 실제 Google 기록 연동 환경이 준비되어 있어, 캘린더·메일·드라이브 기록을 찾아 반영할 수 있어요."

---

### 장면 2: 데모 예시 실행 — "MABC 2026 결선 준비" (약 45초)
**목표**: 카드 생성 흐름 시연 (입력 → 처리 → 카드 출력)

1. 데모 예시 중 "MABC 2026 결선 준비" 버튼 클릭
2. 입력창에 "MABC 2026 결선 준비" 표시됨 확인
3. "카드 생성" 버튼 클릭
4. 처리 상태 표시: "기록을 정리하고 있어요…" (프로그레스 바)
5. 생성된 카드 출력:
   - 업무명: MABC 2026 결선 준비
   - 종류: 검토/의사결정 대기 업무
   - 상태: 대기 중
   - 현재 상태 설명: 초안 완료, 피드백 반영 대기, 제출 마감 9/16 18:00
   - 첫 행동: 피드백 오면 반영해서 제출 준비 마무리
   - 주의사항: 자료 검토 요청 보냈으나 답 없음, 제출 마감 9/16 18:00
   - 근거 펼치기: 캘린더/메일/메모/투두 기록 요약

**나레이션/자막 예시**:
> "데모 예시로 'MABC 2026 결선 준비'를 선택해볼게요.
> 카드 생성 버튼을 누르면, 기록을 정리하는 중 표시가 나오고...
> 잠시 후 카드가 생성됐어요.
> 현재 상태는 '대기 중'이고, 초안 완료 후 피드백을 기다리고 있어요.
> 제출 마감은 9월 16일 18시라서, 피드백 도착 시점과 반영 시간을 감안해야 해요.
> 캘린더에는 발표 리허설 일정이 잡혀 있고, 메일로는 자료 검토 요청을 보냈지만 아직 답이 없어요."

---

### 장면 3: 다른 데모 예시 — "프로젝트 전환 정리" (약 30초)
**목표**: 다른 시나리오도 동작함을 보여주기

1. "데모 예시로 체험하기" 버튼 클릭
2. "프로젝트 전환 정리" 선택 (또는 입력창에 직접 입력)
3. 카드 생성 → 결과 확인:
   - 토스·인계 대상 업무
   - 담당자 미확정 상태
   - 인수인계 포인트 3개 확인됨

**나레이션/자막 예시**:
> "이번엔 '프로젝트 전환 정리'를 해볼게요.
> 토스 대상 업무를 정리 중인데 담당자가 아직 확정되지 않은 상황이에요.
> 인수인계 포인트 3개는 확인된 상태고, 다음 주 월요일 인계 예정이에요."

---

### 장면 4: 실제 데이터 연동 구조 설명 (약 30초, 선택)
**목표**: 실제 Google 데이터 연동 가능성 보여주기

**옵션 A (실제 데이터 조회 시연 — Timely 환경)**:
- Timely 환경에서 composio_execute로 실제 Google 데이터 조회 결과 제시
- 캘린더 이벤트, Gmail 프로필, Drive 파일 목록 등
- ※ 이 장면은 Vercel 배포본에서는 불가, Timely 환경에서 별도 촬영

**옵션 B (구조 설명 — 배포본 화면 + 자막)**:
- "실제 기록 연동" 상태 배너가 보이는 화면 제시
- 자막/나레이션으로 구조 설명:
  > "이 서비스는 Composio를 통해 Google Calendar, Gmail, Drive와 연결돼요.
  > API 키와 토큰은 서버 측에서만 관리해서 보안에 신경 썼고,
  > 연결된 도구에서 실제 기록을 찾아 카드 생성에 반영할 수 있어요."

**규정 정합성 참고**:
- 제9조 제3항: MCP 활용 허용
- 제5조 제3항: 공개 외부 API(Google Calendar/Gmail/Drive) 사용 허용
- 제9조 제6항: API 키·토큰 소스코드/PRD/서비스 UI 노출 금지 → 서버 측 관리
- 제5조 제5항: 타인 개인정보 동의 없는 노출 금지 → 본인 계정, 필터링 적용

## 3. 촬영 시 유의사항

### 3.1 개인정보 노출 방지
- 실제 Google 데이터 조회 장면 포함 시:
  - 메일 본문 전체 노출 지양 (제목/발신자/시간 위주)
  - 캘린더 참석자 이메일 마스킹 또는 생략
  - 드라이브: 파일명/타입/수정일시만 표시
- 본인 계정 데이터라도 시연 화면 노출 범위 주의 (제5조 제5항)

### 3.2 편집 가이드
- 3분 이내로 컷 편집
- 불필요한 로딩 시간 단축 (편집으로 건너뛰기 가능)
- 자막 추가 시 가독성 좋은 폰트 사용
- MP4(H.264) 포맷, 720p 이상 권장

### 3.3 제출용 파일명
- 권장: `mabc-2026-rbst-demo.mp4` 또는 `mabc-2026-데모영상.mp4`
- 파일 크기 확인 (과도한 고용량 주의)

## 4. 대안 시나리오 (실제 데이터 부족 시)

### 4.1 캘린더 오늘 일정 없음 문제
- 실제 데이터: 오늘(2026-09-13) 캘린더 일정 없음
- 대안:
  - 다른 날짜 범위 조회 (예: 이번 주, 다음 주)
  - demoMap 가상 데이터와 혼합 시연
  - "오늘 일정 없음 → 다른 기록(메일/드라이브) 기반 카드 생성"으로 흐름 전환

  - 데모용 가상 데이터(demoMap)에 의존
  - "실제 데이터 조회 → 기록 없는 경우 데모 예시로 체험" 흐름 보여주기
