# PRD_v3 — 갈피(ResumeCard): 개업 변호사 대상 사건 재개 카드 서비스

> work-resume(예선 제출 스킬) 기반, Vercel 독립 배포 웹 서비스 MVP.
> 타겟: 개업 변호사(송무 중심 개인·소형 법률사무소).
> 공백·미확정은 "확인 필요"로 표시.

---

## 0. 호출 대상 스킬 및 안전 점검 결과

| 항목 | 내용 |
|---|---|
| 스킬명 | work-resume (업무 재개 카드) |
| 예선 제출 | 본인 예선 제출 스킬 (확인 완료) |
| 목적 | 흩어진 사건 기록을 재정리해 "이어가고 싶은 사건 하나"에 대한 재개 카드(현재 상태 → 첫 행동 → 주의사항 + 근거) 생성 |
| 데이터 출처 | ① 사용자 직접 입력(질문/사건번호 + 선택 메모) |
| | ② 연결 환경 시 Timely 앱 커넥터(Gmail·Calendar·Docs·Sheets·Drive) |
| | ③ 외부 기록 없을 때 보충 입력/데모 경로 |
| | ④ 데모용 예시 데이터 |
| 설정 | 런타임 LLM = Solar Pro 4 (API 키: Vercel 환경변수, 이름만 PRD 8번에 기재, 값은 등록 시 사용자 입력) |
| 외부 전송 | /api 서버리스 함수가 Solar Pro 4 API만 호출. 그 외 외부 주소 요청 없음. 클라이언트(index.html)에 키·프록시 주소 0개 |
| 권한 | 셸 실행·파일 시스템 접근·다른 계정/토큰 요구 없음 |
| 결과 | 통과 — 호출 대상 스킬로 사용 가능 |

**이 스킬만으로 할 수 없는 일 3가지**
1. 연결된 MCP 도구 없는 환경에서 실제 외부 사건 기록을 대신 가져오지 못함 → 보충 입력/데모 경로로 대체
2. 계정·저장값 없는 첫 방문에서 이전 맥락 복원 불가 → 이번 MVP는 1건 재개 카드 중심
3. 토스·인계용 별도 포맷, 교대·인수인계 템플릿, 히스토리 누적 관리는 제외

## 1) 한 줄 정의

```
(수정)
몇 주 만에 다시 여는 사건 하나에 대해 변호사가 지금 상태와 다음에 할 일, 한 가지를 근거와 함께 받는 웹 서비스
"이 사건 어디까지 갔더라?" 가 "여기부터 하자"가 된다.
찾는 시간은 없애고, 그렇게 판단한 근거는 남긴다.

신규 추가, 이하 삭제(2절과 중복)
```
**[누구를 위해]**
- 개업 변호사(송무 중심 개인·소형 법률사무소)

**[무엇을 해주는가]**
- "이어가고 싶은 사건 하나(사건번호/질문)"만 입력
- 흩어진 사건 기록(메일·메신저·초안·사무장 메일·캘린더 등)을 다시 훑지 않고도
- **사건 재개 카드(사건번호/사건명/다음 기일 + 현재 상태 → 첫 행동 → 주의사항 + 근거)** 1장을 바로 받아서
- 다음 행동으로 이어가게 하는 웹 서비스

## 2) 타깃 사용자

| 구분 | 내용 |
|---|---|
| 구체적인 한 사람 | 송무를 주로 다루는 개업 변호사(개인·소형 법률사무소). 준비서면 제출 주기·기일 간격 1~3주, 한 사건을 몇 주 만에 다시 집어드는 일이 일상. |
| 상황 예시 | - 연휴·휴가 복귀 후 밀린 사건 재개<br>- 다른 사건 진행 중 잠시 놓았던 사건 재개<br>- 사무장/의뢰인 토스 사건 맥락 파악<br>- 변론기일·항소기간 등 시간 압박 사건 우선순위 확인 |
| 접근성 | - 한국어 인터페이스<br>- 별도 계정 없이 URL 접속<br>- 사무실 PC에서 전자소송 상시 열어두는 환경 → 웹 접근 장벽 낮음 |
| 선정 근거 | - 재개가 업무 기본 형태(1~3주 주기)<br>- 대형 로펌은 사건관리시스템·기록 정리 인원 별도<br>- 개업 변호사는 그 자리가 비어 있고 도구 도입을 본인이 결정 → 타겟 유리 |
| 주의 | "없으면 치명적"(놓친 기록·기한 → 고객 패소, 금전/명예 리스크)은 선정 근거로만 사용, 제출물 문구는 톤 조절 |
```(수정)
1. 구체적인 사람에 줄 나누기로 가독성 향상하자.
2. 상황 예시에 연휴휴가 복귀 후 밀린 사건 재개는 삭제
3. 웹 접근 장벽 낮음을 서비스 접근 장벽 낮음으로 수정(서비스를 갈피라고 표기하는게 맞을지는 고민)
4. 주의는 이 서비스의 주의를 의미하는건가? 중요성 등으로 제목 바꾸고 없으면 안되는 결정적 이유롤 적는게 좋을 것 같은데 검토해줘(놓친 기록이나 기한이 고객 패소, 금전/명예 리스크로 이어질 수 있음)
```

## 3) 문제

| 층위 | 내용 |
|---|---|
| **재개 마찰** | 몇 주 만에 다시 집어드는 사건이 일상, 다시 열 때마다 흩어진 맥락 조립 부담 |
| **흩어진 현재 위치** | 사건 공식 상태는 전자소송에 있지만, 재개에 필요한 건 메일/메신저/초안/사무장 메일/캘린더 등에 흩어짐 → "내가 어디서 끊었는지" 바로 알기 어려움 |
| **방향 혼재 리스크** | 서로 다른 방향 기록 공존 시(예: 의뢰인 합의 의향 vs 준비서면 전액 다툼) 무엇이 현재 방침인지 확인 부담, 추정/요약으로 한쪽 고르는 방식은 이 직군에서 위험 |
| **직접 입력만으로 해결 불가** | - 사용자가 기록 장소 기억해 매번 찾아 넣어야 함<br>- 여러 기록 중 최신 판단 어려움<br>- 최신 못 믿으면 재사용 안 함 → 서비스 사용 안 함 |
| **그래서** | "이어가고 싶은 사건 하나"만 묻고, 그 단서로 연결된 도구·MCP에서 관련 기록 스스로 찾아 모음. 사용자는 기록 찾아다니지 않고 결과(카드)만 확인 |

## 5) 핵심 기능

### P0 (결선 데모 필수, 최대 4개)

**① 입력 접수**
- "이어가고 싶은 사건 하나"를 질문형 또는 사건번호형으로 입력
- 필요 시 최근 한 줄 메모·기록 요약·토스 맥락 단서(선택) 첨부
- placeholder: "이어가고 싶은 사건을 질문이나 사건번호로 알려줘"
- 예시: "2026가단12345 손해배상 — 합의/서면 방향", "2026가단67890 임대차 — 원상복구비 반박", "2026나54321 공사대금 항소 — 우선 확인"

**② 서비스 주도 처리 (기록 탐색 로직 + 충돌·대기·확인 필요 처리 + 다중 사건 상한)**
- 입력 단서로 서비스 로직이 관련 항목 정리
- 연결 환경: **Timely 앱 커넥터(Gmail, Google Calendar, Google Docs, Google Sheets, Google Drive) 중 사용자 선별 도구**로 관련 기록 탐색
- MVP 우선 반영: Google 관련 5개, 나머지는 사용자 선별 따라 확장
- 미연결/심사 환경: 사용자 입력 메모·키워드·보충 텍스트 기준으로 처리 + **심사용 데모/보충 경로 별도 확보**로 핵심 로직 실제 흐름 보이게 함

**③ 사건 재개 카드 출력**
- 카드 1장 구성:
  - 상단: 사건번호/사건명/다음 기일(D-n)
  - 현재 상태(라벨)
  - 첫 행동 1개 + 근거 1줄
  - 주의사항(기한/리스크/대기/충돌/확인 필요)
  - 근거 펼침/접기(핵심 1줄 우선, 펼치면 상세)
- 다중 사건 식별 시: 우선 사건 카드 1장 + 나머지는 요약·목록("그 외 ○○건 더 있어요") 안내

**④ 체험(데모) 경로 (가상 데이터 기반, 선택형)**
- 연결/연동/계정 환경 아니어도 핵심 흐름 실제 진행 흐름 보임
  - 입력 → 처리 상태 표시 → 카드 출력
  - 상태 판정 → 첫 행동 → 주의사항 + 근거
  - 충돌 처리
- 단순 정적 예시 카드 노출이 아니라 **실제 로직이 돌아가는 구조**
- 데모 데이터: 가상 사건 3건 × 각 사건 관련 기록 4~5건, 각 기록 상태 충돌/대기/완료 등 다양하게 배치
- 데모 진입:
  - '데모 예시로 체험하기' → 예시 사건 3건이 칩(버튼) 목록
  - 하나 선택 → 해당 사건 가상 기록 4~5건으로 카드 생성 흐름 체험
  - 필요 시 다른 예시 사건도 선택 가능
- 예시 표지: "데모 예시" 문구, 필요 시 "업스테이지 MABC 2026 대회 맥락 예시" 보충

### P1 (있으면 좋지만 당장 아닌 것)

- 태그/키워드 입력 보조(자동 추천 제외), P0-1에 자연스럽게 녹아 있는 수준
- 결과 화면 UX 다듬기(근거 펼침/접기, 핵심 근거 우선 노출 등)
- 진입 문구("완벽하게 재개할 필요 없이, 5분만 이어서 보기") 얇게 사용
- "그 외 ○○건 더 있음" + "다른 업무 보기" 연결점

## 6) 스킬 매핑

| 기능(P0) | 예선 스킬 / 연동 커넥터 | 공개 데이터 출처 / API 주소 | 비고 |
|---|---|---|---|
| 전체 카드 생성 로직 | work-resume (본인 예선 제출, 안전 점검 통과) | /api가 Solar Pro 4 API 직접 호출해 카드 생성 로직 수행. client 키 노출 없음 | 스킬 자체 배포/호출 안 함. 핵심 로직(상태 판정 → 첫 행동 → 주의사항 + 충돌·근거 처리)을 /api에서 재현 |
| 입력 처리 | work-resume 로직 기반 | 사용자 입력(질문형/사건번호형 + 선택 메모) — /api 수신 | 직접 입력 |
| 기록 탐색 (연결 환경) | **Timely 앱 커넥터 중 사용자 선별 도구** — MVP 우선: **Gmail, Google Calendar, Google Docs, Google Sheets, Google Drive** | 각 Timely 앱 커넥터 제공 범위(메일·캘린더·문서·시트·드라이브)에서 관련 기록 탐색. 실제 제공 기능·도구 범위는 연결/연동 시 확인 필요 | 데모/보충 경로(P0-4)와 분리. 규정상 MCP 활용 허용(제9조 제3항) 범위 내 사용, 외부 데이터 활용 시 저작권·출처 표기 준수 |
| 데모 경로 | work-resume 로직 기반 | 데모 모드용 가상 예시 데이터(미리 준비) — /api가 동일 로직으로 처리 | 예시 표지 포함 |

**주의**: 배포된 웹 서비스는 work-resume 스킬을 호출하지 않는다. /api 서버리스 함수가 위 데이터 출처를 직접 호출/처리

하고, 스킬 코드·스킬 문서는 서비스에 포함하지 않는다.

## 8) 필요 설정

### 8-1. 배포 연결 (Vercel 커넥터)

- Vercel에 배포. 값 취급 없음(설정 존재만 확인).

### 8-2. 서비스 키 (Vercel 환경변수)

| 이름 | 용도 | 발급처 | 값 |
|---|---|---|---|
| SOLAR_API_KEY | /api에서 Solar Pro 4 호출 시 인증용 | 대회 제공 크레딧/키 | (등록 시 사용자 직접 입력, 대화에 값 적지 않음) |

- 위 표에 있는 이름만 Vercel 환경변수 등록. 표에 없는 변수 등록 안 함.
- **Google 앱 커넥터(Gmail, Google Calendar, Google Docs, Google Sheets, Google Drive) 등 외부 서비스 인증은 Vercel 환경변수에 키 하드코딩하지 않음.**
  - 커넥터별 인증은 Timely 연결/OAuth 등 Timely가 정한 방식으로 처리
  - 소스코드·배포물·PRD·서비스 UI에 인증정보 노출 금지(제9조 제6항)
- 환경변수는 /api 서버리스 함수만 읽음. 클라이언트(index.html)에 키·프록시 주소 0개.

### 8-3. 사용자 프로필 (웹 화면 입력 → localStorage)

- 계정 없이 사용. 저장할 프로필 최소화.
- 입력 예시·최근 입력 등 편의성 저장만 localStorage 가능(재방문 시 묻지 않음, 초기화 버튼 제공).
- 민감 정보 저장 금지.

## 9) 데이터 규칙

| 구분 | 규칙 |
|---|---|
| 출처·기준 시각 표기 | 카드 내 근거에 "어떤 입력/기록을 근거로 했는지" 범위 표시. 데모 모드면 "데모 예시" 표지 |
| 없는 값 | '확인 불가'로 표시(추정 금지) |
| 추정 | 합리적 추정 가능 시에만 [추정] 태그로 명시. 근거 없는 과추정 금지. 확정적 종료 표현만 완료로 판정("완료", "다 했", "끝났다", "더 할 일 없음" 등). "거의 끝남", "마무리 예정" 등은 진행 중/확인 필요 |
| 키·프록시 주소 | 서버(/api)만. 클라이언트 0개 |
| 최소 권한 | /api는 Solar Pro 4 API와 데모 데이터만 접근 |
| 외부 데이터 활용 | 저작권·출처 표기 준수, 타인 저작물·동의 없는 개인정보 포함 금지 |
| 개인정보 포함 커넥터 자료 | 특히 **Gmail·Google Drive 등 개인정보 포함 가능 커넥터 자료** 활용 시: 업무상 필요한 개인 특정 정보(이름·연락처·메일주소) 범위만 표시, 나머지 출력 제외 + "민감정보로 출력하지 않음" 명시. 민감정보 **저장하지 않음**(localStorage 등 포함) |
| 개인정보 처리 | 입력은 요청 단위로만 처리, 서버 미저장. 심사 응답 및 PRD 문구 준비 필수 |

## 10) 성공 기준 (데모 시나리오 + 시크릿 창 테스트)

### 데모 시나리오 (P0 검증용)

| # | 시나리오 | 확인 내용 |
|---|---|---|
| 1 | 질문형 입력 → 카드 1장 출력 | "2026가단12345 손해배상 — 합의/서면 방향" → 사건번호/사건명/다음 기일(D-n) 상단, 현재 상태(확인 필요·기록 충돌), 첫 행동 + 근거, 주의사항, 근거 펼침 확인 |
| 2 | 사건번호형 입력 → 자동 데모 라우팅 | "2026가단67890 임대차보증금" → 자동 데모 경로 연결 → 카드 출력 |
| 3 | 기록 없음 | 연결 도구에서 관련 기록 없음 → 보충/데모 제안 안내 (중립·도움 톤) |
| 4 | 데모 예시 체험 | 칩 클릭 → 예시 표지("데모 예시") + 실제 로직 흐름(처리 상태 표시 → 카드 출력) 확인 |
| 5 | 충돌 상황 데모 | "확인 필요(기록 충돌)" + 첫 행동이 "무엇을 어디서 확인/행동할지" 형식 제시(의뢰인에게 합의 의사 확인 후 서면 방향 결정) |
| 6 | 다중 사건 데모 | 우선 카드 1장 + "그 외 ○○건 더 있어요" 요약·목록 |
