# PRD — ResumeCard (work-resume 기반 업무 재개 카드 서비스)

> 이 PRD는 skill-to-service 미니 PRD(에이전트에게 주는 설계도)다.
> work-resume(예선 제출 스킬)을 기반으로 Vercel에 독립 배포하는 웹 서비스 MVP의 설계도.
> 공백·미확정은 "확인 필요"로 표시한다.

---

## 0. 호출 대상 스킬 및 안전 점검 결과 (skill-to-service A-0 반영)

| 점검 항목 | 내용 |
|---|---|
| 스킬명 | work-resume (업무 재개 카드) |
| 예선 제출 여부 | 본인 예선 제출 스킬 (확인 완료) |
| 목적 | 흩어진 업무 기록을 재정리해 "이어가고 싶은 일 하나"에 대한 재개 카드(현재 상태 → 첫 행동 → 주의사항 + 근거) 생성 |
| 데이터 출처 | ① 사용자 직접 입력(질문형/태그·키워드형 + 선택 메모) ② 연결 환경 시 MCP 도구(메일·캘린더·메모 등) ③ 외부 기록 없을 때 서비스 내부 대화/기록 참고(보조, 실제 환경 확인 필요) ④ 데모 모드용 예시 데이터 |
| 필요한 설정 | 서비스 런타임 LLM = Solar Pro 4 (API 키: Vercel 환경변수, 이름만 PRD 8번에 기재, 값은 등록 시 사용자가 직접 입력) |
| 외부 전송 | /api 서버리스 함수가 Solar Pro 4 API만 호출. 그 외 외부 주소로는 요청하지 않음. 클라이언트(index.html)에는 키·프록시 주소 0개 |
| 권한 요구 | 셸 실행·파일 시스템 접근·다른 계정/토큰 요구 없음 |
| 안전 점검 결과 | 통과 — 호출 대상 스킬로 사용 가능 |

**이 스킬만으로는 할 수 없는 일 3가지 (PRD 범위 설정에 반영)**
1. 연결된 MCP 도구(메일·캘린더·메모)가 없는 환경에서 실제 외부 기록을 대신 가져오지 못함 → 보충 입력/데모 경로로 대체
2. 사용자 계정·저장값이 없는 첫 방문에서 이전 맥락(지난 재개 이력 등)을 복원하지 못함 → 이번 MVP는 1건 재개 카드 생성이 중심
3. 토스·인계용 별도 포맷, 교대·인수인계 템플릿, 히스토리 누적 관리는 이번 MVP 범위에서 제외

## 1) 한 줄 정의
출근·휴가 복귀·프로젝트 전환·토스/인수인계 상황에서, "이어가고 싶은 일 하나"만 입력하면 흩어진 기록을 다시 훑지 않고도 **업무 재개 카드(현재 상태 → 첫 행동 → 주의사항 + 근거)** 1장을 바로 받아서 다음 행동을 이어갈 수 있게 하는 웹 서비스.

## 2) 타깃 사용자 (WHO)
- 구체적인 한 사람: 복귀·전환·토스 상황 직후, 흩어진 메모·회의록·메일·메신저·투두·작업일지를 다시 읽어야 다음 행동을 잡을 수 있는 지식노동자.
- 상황 예시: 출근 직후 어제 업무를 찾고 싶은 사람, 일주일 만에 프로젝트에 다시 들어온 사람, 다른 사람에게 토스받은 업무를 이어야 하는 사람, 휴가 복귀 후 밀린 일을 정리해야 하는 사람.
- 접근성·언어: 한국어 인터페이스, 별도 계정 없이 URL로 접속.

## 3) 문제
- 복귀·전환·토스·인수인계·휴가 복귀·프로젝트 전환 등에서, 흩어진 기록(메모·회의록·메일·메신저·투두·작업일지 등)을 다시 훑어야 다음 행동을 잡을 수 있는 구조.
- 기록을 찾는 것 자체가 번거롭고, 찾는 동안 시야가 흐려짐.
- 기록이 여러 곳에 쌓이면 어느 것이 최신인지 판단이 어려워지고, 최신 기록을 못 믿으면 재사용하지 않게 됨.
- 사용자가 기록할 곳을 기억해서 매번 찾아 넣어야 하는 부담도 있음.

## 4) 트리거 (WHEN)
- 사용자가 URL로 들어와 직접 입력하는 **온디맨드 호출형** 서비스.
- 트리거 순간 예시: 출근 직후, 휴가 복귀 직후, 프로젝트 전환 직후, 토스/인수인계 받은 직후, 일주일 만에 재개할 때.
- 서비스가 먼저 가야 하는 방식(공유 링크·알림)은 이번 MVP 범위에서 제외.

## 5) 핵심 기능

### P0 (결선 데모 필수, 최대 4개)
1. **입력 접수**: "이어가고 싶은 일 하나"를 질문형 또는 태그·키워드형으로 입력. 필요하면 최근 한 줄 메모·기록 요약·토스 맥락 단서(선택) 첨부.
   - placeholder: "이어가고 싶은 일을 질문이나 태그/키워드로 알려줘"
   - 예시 노출(시간 특정 표현 제외): "A 프로젝트 어디까지 했지?", "분기 검토", "B팀 답변 대기"
2. **서비스 주도 처리 (기록 탐색 로직 + 충돌·대기·확인 필요 처리 + 다중 업무 상한)**: 입력된 단서로 서비스 로직이 관련 항목을 정리. 연결 환경에서는 **Timely 앱 커넥터(Gmail, Google Calendar, Google Docs, Google Sheets, Google Drive 등) 중 사용자가 선별한 도구**로 관련 기록을 탐색. MVP 우선 반영 대상은 **Google 관련 5개(Gmail, Google Calendar, Google Docs, Google Sheets, Google Drive)**로 하고, 나머지는 사용자 선별에 따라 확장. 미연결/심사 환경이면 사용자가 입력한 메모·키워드·보충 텍스트를 기준으로 처리하고, **테스트용·심사용 데모/보충 경로를 별도로 확보**해 핵심 로직이 실제 돌아가는 흐름이 보이게 함. (실제 각 커넥터가 제공하는 기능·도구 범위는 연결/연동 시 확인 필요)
3. **업무 재개 카드 출력**: 카드 1장 — 업무명/종류 상단 → 현재 상태(라벨) → 첫 행동 1개 + 근거 1줄 → 주의사항(기한/리스크/대기/충돌/토스·인계 포인트) → 근거 펼침/접기(핵심 1줄 우선, 펼치면 상세). 다중 업무가 식별되면 우선 업무 카드 1장만 출력하고 나머지는 요약·목록으로 안내.
4. **체험(데모) 경로(가상 데이터 기반, 선택형 예시 체험)**: 연결된 도구·MCP 연동 환경이 아니어도 핵심 흐름(입력 → 처리 상태 표시 → 카드 출력, 상태 판정 → 첫 행동 → 주의사항 + 근거, 충돌 처리)이 실제로 진행되는 흐름을 예시로 보여줌. 단순 정적 예시 카드 노출이 아니라 **실제 로직이 돌아가는 구조**. 데모 데이터는 가상 업무 3건 × 각 업무 관련 기록 4~5건으로 구성, 각 기록의 상태는 충돌/대기/완료 등으로 다양하게 배치.
   - **데모 진입 방식**: '데모 예시로 체험하기' 선택 시 예시 업무 3건이 작은 목록으로 보이고, 그중 하나를 골라 해당 업무의 가상 기록 4~5건으로 카드 생성 흐름을 체험. 필요하면 다른 예시 업무도 선택 가능.
   - **예시 표지**: "데모 예시" 문구를 기본으로 하고, 필요 시 "업스테이지 MABC 2026 대회 맥락 예시" 정도로 보충. 실제 업무명/맥락 명칭은 예시 업무의 구체적 이름으로 채우며, 지금은 업스테이지 MABC 2026 대회 맥락의 예시 업무 3건(예: MBCD 프로젝트 / MABC 2026 결선 준비 / 대회·과제 관련 또 다른 업무 등)으로 구성.

### P1 (있으면 좋지만 당장 아닌 것)
- 태그/키워드 입력 보조(자동 추천 제외), P0-1에 자연스럽게 녹아 있는 수준으로만.
- 결과 화면 UX 다듬기(근거 펼침/접기, 핵심 근거 우선 노출 등).
- 진입 문구("완벽하게 재개할 필요 없이, 5분만 이어서 보기")를 필요한 곳에 얇게 사용.
- "그 외 ○○건 더 있음" + "다른 업무 보기" 연결점(다중 업무 식별 시).

## 6) 스킬 매핑

| 기능(P0 번호) | 사용할 예선 스킬 / 연동 커넥터 | 공개 데이터 출처 / API 주소 | 비고 |
|---|---|---|---|
| 전체 카드 생성 로직 | work-resume (본인 예선 제출 스킬, 안전 점검 통과) | /api가 Solar Pro 4 API를 직접 호출해 카드 생성 로직 수행. client에는 키 노출 없음. | 스킬 자체 배포/호출 안 함. 핵심 로직(상태 판정 → 첫 행동 → 주의사항 + 충돌·근거 처리)을 /api에서 재현 |
| 입력 처리 | work-resume 로직 기반 | 사용자 입력(질문형/태그·키워드형 + 선택 메모) — /api가 수신 | 직접 입력 |
| 기록 탐색 (연결 환경) | **Timely 앱 커넥터 중 사용자 선별 도구** — MVP 우선: **Gmail, Google Calendar, Google Docs, Google Sheets, Google Drive** | 각 Timely 앱 커넥터가 제공하는 범위(메일·캘린더·문서·시트·드라이브)에서 관련 기록 탐색. 실제 제공 기능·도구 범위는 연결/연동 시 확인 필요. | 데모/보충 경로(P0-4)와 분리. 규정상 MCP 활용 허용(제9조 제3항) 범위 내에서 사용, 외부 데이터 활용 시 저작권·출처 표기 준수 |
| 데모 경로 | work-resume 로직 기반 | 데모 모드용 가상 예시 데이터(미리 준비) — /api가 동일 로직으로 처리 | 예시 표지 포함 |

**주의**: 배포된 웹 서비스는 work-resume 스킬을 호출하지 않는다. /api 서버리스 함수가 위 데이터 출처를 직접 호출/처리하고, 스킬 코드·스킬 문서는 서비스에 포함하지 않는다.

## 7) 입력·출력

### 입력
- 메인 입력: 짧은 텍스트 1개(질문형 또는 태그·키워드형). placeholder + 예시 문구 2~3개 노출.
- 선택 입력(얇게): 최근 한 줄 메모·기록 요약·토스 맥락 단서(보충용, 필수 아님).
- 보조 UI: "데모 예시로 체험하기" 버튼/링크(입력창 근처, 작게, 보조 위치).

### 출력
- 기본: 업무 재개 카드 1장
  - 업무명/종류 상단
  - 현재 상태(라벨 가능: 진행 중/대기/확인 필요/완료/분류 확인 필요 등)
  - 첫 행동 1개 + 근거 1줄
  - 주의사항(기한/리스크/대기/충돌/토스·인계 포인트)
  - 근거 펼침/접기(핵심 1줄 기본, 펼치면 상세 근거)
- 충돌/확인 필요: 그대로 표시, 하나로 덮지 않음
- 다중 업무: 우선 카드 1장 + 그 외 요약·목록
- 처리 중 상태 표시: "기록을 찾고 있어요…" 문구 + progress bar, 버튼 비활성화
- 기록이 없을 때: "연결된 도구에서 관련 기록을 찾지 못했어요." + 보충 입력/데모 제안 (중립·도움 톤)
- 작업 실패: "기록을 불러오는 중 문제가 있었어요. 잠시 후 다시 시도해 주세요." (기록 없음과 구분)

## 8) 필요 설정

### 8-1. 배포 연결 (Vercel 커넥터)
- Vercel에 배포. 값 취급 없음(설정 존재만 확인).

### 8-2. 서비스 키 (Vercel 환경변수)
| 이름 | 용도 | 발급처 | 값 |
|---|---|---|---|
| SOLAR_API_KEY | /api에서 Solar Pro 4 호출 시 인증용 | 대회 제공 크레딧/키 | (등록 시 사용자가 직접 입력, 대화에 값 적지 않음) |

- 위 표에 있는 이름만 Vercel 환경변수로 등록. 표에 없는 변수는 등록하지 않음.
- **Google 앱 커넥터(Gmail, Google Calendar, Google Docs, Google Sheets, Google Drive) 등 외부 서비스 인증은 Vercel 환경변수에 키를 하드코딩하지 않는다.** 커넥터별 인증은 Timely 연결/OAuth 등 Timely가 정한 방식으로 처리하며, 소스코드·배포물·PRD·서비스 UI에 인증정보를 노출하지 않는다(제9조 제6항).
- 환경변수는 /api 서버리스 함수만 읽음. 클라이언트(index.html)에는 키·프록시 주소 0개.

### 8-3. 사용자 프로필 (웹 화면 입력 → localStorage)
- MVP에서는 계정 없이 사용. 사용자별로 저장할 프로필은 이번 MVP에서 최소화.
- 입력 예시·최근 입력 등 편의성 저장만 localStorage로 가능(재방문 시 묻지 않음, 초기화 버튼 제공).
- 민감 정보 저장 금지.

## 9) 데이터 규칙
- 출처·기준 시각 표기: 카드 내 근거에 "어떤 입력/기록을 근거로 했는지" 범위를 표시. 데모 모드면 "데모 예시" 표지.
- 없는 값: '확인 불가'로 표시(추정 금지).
- 추정: 합리적으로 추정할 수 있는 경우에만 [추정] 태그로 명시. 근거 없는 과추정 금지.
- 키·프록시 주소는 서버(/api)에만. 클라이언트에 0개.
- 최소 권한: /api는 Solar Pro 4 API와 데모 데이터만 접근.
- 외부 데이터 활용 시 저작권·출처 표기 준수, 타인 저작물·동의 없는 개인정보 포함 금지. 특히 **Gmail·Google Drive 등 개인정보가 포함될 수 있는 커넥터 자료**를 활용하는 경우, 업무상 필요한 개인 특정 정보(이름·연락처·메일주소) 범위만 표시하고 나머지는 출력 제외 + "민감정보로 출력하지 않음" 명시. 민감정보는 **저장하지 않음**(localStorage 등 포함).
- 확정적 종료 표현만 완료로 판정("완료", "다 했", "끝났다", "더 할 일 없음" 등). "거의 끝남", "마무리 예정" 등은 진행 중/확인 필요로 처리.

## 10) 성공 기준 (데모 시나리오 + 시크릿 창 테스트)

### 데모 시나리오 (P0 검증용)
1. 질문형 입력 → 카드 1장 출력(상태 → 첫 행동 → 주의사항 + 근거, 근거 펼침 가능)
2. 태그/키워드 입력 → 카드 1장 출력
3. 기록 없음 상황 → "연결된 도구에서 관련 기록을 찾지 못했어요." + 보충/데모 제안
4. 데모 예시 체험 → 예시 표지와 함께 실제 로직 흐름(처리 상태 표시 → 카드 출력) 확인
5. 충돌 상황 데모 → "확인 필요(기록 충돌)" + 첫 행동이 "무엇을 어디서 확인/행동할지" 형식으로 제시
6. 다중 업무 데모 → 우선 카드 1장 + 그 외 요약·목록

### 시크릿 창 테스트 (필수)
- 저장값·계정 없는 브라우저(시크릿 창)로 첫 방문했을 때:
  - 안내가 스스로 나오고(서비스명 + 한 줄 설명 + 입력 필드 + 예시 문구 + 버튼)
  - 최소 기능(입력 → 카드 출력)이 동작하는지 확인
  - 데모 예시 체험도 가능한 경우 확인

## 11) 제외 범위
- 저장소 자동 연동 전체 (연결 가능한 범위에서만)
- 히스토리 누적·관리 (이번 MVP는 1건 재개 카드 중심)
- 토스·인계용 별도 포맷, 교대·인수인계 템플릿
- 태그 자동 추천
- 공유 링크·알림으로 서비스가 먼저 가는 방식
- 연결 환경(MCP) 실제 연동 범위 확정 전, 연동 전제 기능 전부
