# 업무 재개 카드 (work-resume)

이전/직전 업무나 할 일을 다시 이어가는 시점에, 흩어져 있던 기록을 뒤적이지 않아도 바로 다음 행동을 이어서 할 수 있도록
'업무 재개 카드' 한 장을 만들어 보여준다. 개인 사용이 기본이고, 교대근무·인수인계용으로도 쓸 수 있다.

이 스킬의 핵심 포인트(요약): 흩어진 기록을 보는 대신 재개 시점에 필요한 정보만 카드로 압축하고,
불확실한 내용은 확정처럼 쓰지 않으며, 충돌은 숨기지 않고 모두 보여준다.
개인정보 중 주민등록번호 같은 민감 정보는 카드에 출력하지 않는다.

## 기획 요약 (심사/전달용)

- **해결하는 불편**: 출근 직후·휴가 복귀·프로젝트 전환·인수인계·토스 상황마다, 여기저기 흩어진 메모/메일/회의록/메신저를 다시 훑어야 next action을 잡을 수 있는 번거로움.
- **대상 사용자**: 개인 업무자, 소수 팀 협업, 교대·인수인계가 있는 업무 환경.
- **해결 방식**: 사용자가 재개 맥락(프로젝트명, 업무 종류, 언급된 기록, "일주일 만에 이어서" 같은 단서)을 주거나, 서비스가 연결된 도구·MCP(메일·캘린더·메모 등)를 통해 관련 업무 자료를 찾아서, 업무별로 **현재 상태 → 첫 행동 → 주의사항** 순서로 된 '업무 재개 카드' 한 장을 출력한다. 태그/키워드를 선택 옵션으로 활용해 관련 업무를 찾을 수도 있다. 연결이 없는 맥락에서는 사용자가 직접 제공한 메모·붙여넣기·요약·키워드 기반으로 동작한다.
- **한 장 카드 원칙**: 분류·상태 판정·첫 행동 제안·주의사항 정리는 모두 '카드 한 장'을 만들기 위한 내부 처리이며, 최종 결과물은 업무별 카드 한두 장으로 압축해 보여준다.
- **기대 효과**: 재개 시 흩어진 기록 탐색 시간을 줄이고, 다음 행동을 바로 시작할 수 있게 돕는다. 불확실한 내용은 확정처럼 포장하지 않아, 후속 확인 부담을 줄인다. 연결된 도구·MCP로 관련 자료를 찾으면 흩어진 기록을 다시 훑는 불편을 더 직접적으로 줄일 수 있다.

## 동작 (단계)

1. 사용자로부터 재개하려는 맥락(프로젝트명, 업무 종류, 언급된 기록, "일주일 만에 이어서", "누구한테 토스" 같은 단서를 받는다.
   없으면 "어떤 업무/프로젝트를 이어서 할 건지" 한두 마디만 더 물어본다.
2. 이 대화 안에서 사용자가 말해준 기록 요약, 붙여넣은 메모·회의록·메일·메신저 텍스트,
   또는 서비스가 연결된 도구·MCP(메일·캘린더·메모 등)를 통해 가져온 관련 업무 자료를 살핀다.
   연결이 없는 맥락에서는 사용자가 직접 제공한 텍스트·요약·키워드 기반으로 동작한다.
   외부 데이터를 활용하는 경우, 가져온 자료의 저작권·출처 표기를 반드시 지켜야 하며,
   타인 저작물·상표·개인정보는 권리자의 동의 없이 포함하지 않는다.
3. 다른 출처의 실제 파일·계정을 임의로 열어보지 않으며, 없는 기록은 지어내지 않는다.
   내부 환경(서비스와 연동된 저장 공간 등)에 저장된 대화/기록을 참고할 수 있는 경우에는
   그 범위에서만 참고한다. 이때 해당 기록의 존재 여부·접근 권한·개인정보 포함 여부는
   실제 환경에 따라 확인이 필요하다.
3. 입력 데이터를 **업무 종류로 구분**한다. (예: 일반 진행 업무, 검토/의사결정 대기 업무, 기한형 업무, 토스·인계 대상 업무 등)
   - 구분하기 모호하면 가장 가까운 유형으로 임시 분류하고, 라벨에 "(분류 확인 필요)"를 붙인다.
4. 구분된 각 업무의 **현재 상태를 아래 5가지 중 하나로 판정**한다.
   - **진행 중**: 실제로 계속 손대고 있거나 이어서 착수 가능한 상태
   - **대기 중**: 자료/응답/승인/누군가의 다음 행동을 기다리고 있는 상태
     - 특히 **자료 대기 중이면 '대기 중'** 으로 판정한다.
   - **완료**: 기록상 끝났고 더 할 일이 남아 있지 않은 상태
   - **확인 필요**: 현재 상태가 무엇인지 확정하기 어렵거나, 기록/확인이 더 필요한 상태
   - (필요 시) 위 4가지로 딱 떨어지지 않으면 가장 가까운 것으로 두고, 라벨에 "(판정 확인 필요)"를 붙인다.
   - 판정 힌트:
     - 답/자료/승인/다음 행동이 누구로부터 오길 기다리는 구조면 **대기 중**.
     - 서로 다른 기록에서 상태가 다르게 보이거나, 얘기가 진행 중인지 끝났는지 불명확하면 **확인 필요**.
     - 기록을 더 봐야 알 수 있으면, 임의로 확정하지 말고 **확인 필요**로 둔다.
     - "어제까지 하다가 멈췄다", "이어서 착수 가능" 같은 단서가 보이면 **진행 중**.
     - "끝났다", "다 했", "더 할 일 없음"처럼 **확정적으로 종료됐다고 보이는 표현**이 기록상 확실하면 **완료**로 본다.
     - "거의 끝남", "마무리 예정", "다음 주에 마무리 예정", "추가 보완 필요"처럼 **종료 가능성이 있지만 아직 확정은 아닌 표현**은 완료로 단정하지 말고, 진행 중 또는 확인 필요(기록 충돌 시)로 둔다.
     - 한 건의 기록만 있고 충돌·대기·리스크가 보이지 않으면 상태 판정이 비교적 단순할 수 있다.
     - 자료가 여러 곳에서 다르게 보이거나, 누가 무엇을 기다리는지 불명확하면 **확인 필요**로 둔다.
       - 서로 다른 기록에서 상태 판단이 충돌하면, 하나로 덮어 판단하지 말고 **확인 필요(기록 충돌)**로 둔다.
     - 판정 결과가 모호하면 단정하지 말고, 라벨에 "(판정 확인 필요)"를 붙인다.
5. 업무마다 **지금 바로 할 일을 하나 뽑고, 그 근거를 함께 표시한다**.
   - 착수 가능하면 첫 행동 1개를 출력하고, **그 근거(관련 기록/마지막 업무의 출처, 어떤 내용을 보고 제안했는지)** 를 함께 보여준다.
   - 마감이 아직 멀고 진행만 유지하면 되는 상태면 "진행 유지, 당장 착수할 일 없음(기한 전)"으로 명시하고, 근거도 함께 정리한다.
6. 내용 요소를 **사실 / 추정 / 확인 필요**로 구분한다.
   - 사실: 기록상 확실한 내용.
   - 추정: 정황상 그렇게 보이지만 확정은 아닌 것.
   - 확인 필요: 결정/확인이 덜 된 것, 누구한테 물어봐야 하는 것.
7. **마감일과 리스크는 주의사항 항목으로 모아서** 카드 안에서 눈에 띄게 관리한다.
   - 마감일/기한, 지연 시 영향, 끊기면 안 되는 연결 포인트, 대기 중인 것 등.
8. **충돌되는 입력 데이터는 하나로 덮지 않고 모두 출력**한다.
   - 서로 다른 기록에서 상태가 다르게 보이면, 각각을 그대로 보여주고 "어느 쪽이 최신/정확한지 확인 필요"로 표시한다.
9. **개인정보를 출력하지 않는다(단, 민감 정보만 제한)**.
   - 주민등록번호 같은 **민감 정보는 카드에 출력하지 않는다.**
   - 이름, 연락처, 이메일 등 업무에서 개인 특정할 수 있는 정보는 출력 가능하며, 토스·인계·담당 확인 등 업무상 필요한 맥락에서는 오히려 필요한 정보로 다룬다.
   - 다만 불필요하게 나열하지 않고, 업무에 필요한 범위에서만 표시한다.

10. **여러 업무가 함께 보이면 업무별로 나누어 각각 카드를 만든다**.
   - 입력 맥락·기록·태그·MCP 자료에서 여러 업무가 식별되면, 업무별로 **현재 상태 → 첫 행동 → 주의사항**을 각각 정리한다.
   - 다만 카드가 지나치게 많아지지 않도록, 재개 맥락과 관련도가 높은 업무를 우선한다. 기본 상한은 주요 카드 5장 정도로 두고, 이를 넘는 업무는 요약·목록으로 안내한다. 정확한 상한·화면 구성은 서비스 MVP에서 조정할 수 있다.
   - 요약·목록 안내는 카드화할 업무가 상한을 넘거나 그 외 업무가 명확히 남는 경우에 붙이며, 적은 수의 단순 입력에서는 굳이 붙이지 않는다.
   - 업무 구분이 애매하거나 하나로 묶는 것이 더 명확한 경우에는 무리하게 쪼개지 말고, 관련 업무들을 묶어 요약 카드 또는 통합 안내로 제시한다.

## 출력 형식 (고정 템플릿)

**업무 재개 카드** — 질문 없이 바로 출력한다. 업무 하나씩, **항상 아래 순서로 동일한 제목**을 사용한다.

```
## [업무명] — [종류]
- 현재 상태: (진행 중 / 대기 중 / 완료 / 확인 필요) 중 하나
  - (짧게 근거). 가능하면 [사실]/[추정]/[확인 필요] 라벨을 붙인다.
- 첫 행동: (업무마다 1개, 또는 당장 착수할 일 없음이면 "당장 착수할 일 없음")
  - (근거): 어떤 기록/맥락을 보고 이 첫 행동을 제안했는지 함께 표시
- 주의사항: (기한, 리스크, 대기 업무, 토스·인계 포인트, 충돌 등)
  - 근거: 첫 행동/상태 판정의 근거가 되는 관련 기록·출처를 함께 표시한다.
```

- **제목과 순서 고정**: 모든 업무 카드는 반드시 "현재 상태 → 첫 행동 → 주의사항" 순서, 동일 제목으로 출력한다.
- **현재 상태 5가지**: 진행 중 / 대기 중 / 완료 / 확인 필요 / (필요시 판정 확인 필요)
  - 자료, 응답, 승인, 누군가의 다음 행동을 기다리는 상황이면 **대기 중**으로 둔다.
  - 기록이 충돌하거나 현재 상태가 불확실하면 **확인 필요**로 둔다.
- **요소 라벨**: 가능한 한 **[사실] / [추정] / [확인 필요]** 라벨을 붙인다.
- 확정되지 않은 내용은 함부로 확정처럼 쓰지 않는다.
- **개인정보는 민감 정보만 제한한다.** 주민등록번호 같은 민감 정보는 출력하지 않으며, 이름·연락처·이메일 등 업무상 필요한 개인 특정 정보는 필요한 범위에서만 사용한다.

### 단순 할 일 출력 (간소화)
- 특별히 복잡한 배경/충돌/리스크가 없는 일반적인 단순 할 일이면, **아래 3가지만**으로 간소화해 출력한다.
  - 현재 상태: (5가지 중 하나)
  - 첫 행동: (1개, 또는 당장 착수할 일 없음)
  - 주의사항: (기한/리스크/대기가 있으면 한 줄, 없으면 "없음")
- 위처럼 단순할 때도 **현재 상태 → 첫 행동 → 주의사항**의 골격은 그대로 유지한다.
- 복잡한 업무, 충돌 있는 업무, 기한·리스크가 중요한 업무는 위 템플릿을 그대로 사용해 더 자세히 출력한다.
  - 예: 한 건의 기록/단서만 있고 충돌·대기·리스크가 보이지 않으면 간소화 여지가 크고,
    여러 기록에서 상태가 다르게 보이거나, 누가 무엇을 기다리는지 불명확하거나,
    마감·지연 영향이 큰 업무는 템플릿을 그대로 사용하는 쪽에 가깝다.

### 주의사항 항목 구성
- 근거: 첫 행동/상태 판정의 근거가 되는 관련 기록·출처를 함께 표시한다.
  - 가능하면 **핵심 근거 1줄** 먼저 보여주고, 필요하면 **상세 근거(참고 범위/기록·출처)**를 함께 표시한다.
  - 서비스 화면에서는 핵심 근거를 우선 보여주고, 상세 근거는 필요 시 펼치도록 구성할 수 있다.
- 기한/마감일이 있으면 명시한다.
- 리스크(지연 시 영향, 끊기면 안 되는 연결 포인트 등)가 있으면 함께 적는다.
- 대기 중인 업무/응답/승인/토스·인계 포인트가 있으면 적는다.
- 충돌이 있으면 하나로 덮지 말고 함께 표시한다.

### 충돌 처리
- 서로 충돌하는 기록이 있으면 하나를 골라 덮지 말고 **모두 보여준다**.
  - 예: "메모: 거의 끝남 / 메일: 아직 검토 중 → 둘 중 어느 쪽이 최신인지 확인 필요"
- 충돌되는 기록이 있으면, 상태 판정을 임의로 하나로 확정하지 말고 **확인 필요(기록 충돌)**로 두고,
  첫 행동은 "충돌 해소 후 재개" 방향으로 제시한다.
- 충돌 내용(어떤 기록이 어떻게 다른지)은 주의사항에 함께 표시한다.

## 출력 품질 점검 (스킬 자체가 확인하는 기준)

카드 출력 후 아래 항목이 가능하면 스스로 점검한다. 어긋나면 출력을 다시 정리한다.

- 각 업무 카드에 **현재 상태 → 첫 행동 → 주의사항** 순서가 지켜졌는가.
- 첫 행동마다 **근거**(어떤 기록/맥락을 보고 제안했는지)가 함께 표시됐는가.
- 미확정 내용이 **확정처럼** 쓰이지 않았는가. (추정/확인 필요는 라벨로 구분)
- 충돌되는 기록이 있으면 **하나로 합쳐 덮지 않고** 모두 보여줬는가.
- 마감일·리스크·대기 포인트가 **주의사항**에 보기 쉽게 모였는가.
- **주민등록번호 같은 민감 정보**가 카드에 출력되지 않았는가.

## 하지 말 것 (부정 제약)

- 추정인데 사실처럼 단정하지 않는다. 불확실하면 '확인 필요'로 표기한다.
- 충돌되는 기록을 임의로 하나로 합쳐 해소하지 않는다.
- 기록에 없는 내용·결정을 만들어내지 않는다.
- 이 대화 밖에서 실제 파일·계정·외부 저장소를 임의로 열어보지 않는다(연결 가능한 범위가 아닌 경우).
- '없던 기록을 생성'하거나 '없는 마감일을 지어내는' 식으로 빈칸을 메꾸지 않는다.
- **민감 정보(주민등록번호 등)는 카드에 출력하지 않는다.** 이름·연락처·이메일 등 업무상 필요한 개인 특정 정보는 필요한 범위에서만 사용한다.

## 예시 (입출력 예시)

### 예시 1 — 복귀 후 업무 재개

입력(단서):
> "어제까지 A 프로젝트 자료 정리하다가 퇴근했고, 오늘부터 다시 보려고요. B팀 답변은 아직 안 왔고, 마감은 금요일."

출력(카드):
```
## A 프로젝트 자료 정리 — 일반 진행 업무
- 현재 상태: 진행 중 (마지막 기록: 어제 자료 정리 도중 퇴근) [사실]
- 첫 행동: 어제 멈췄던 자료 정리 지점부터 이어서 검토
  - (근거): "어제까지 자료 정리하다가 퇴근" 단서와 "오늘부터 다시 보려"는 의도
- 주의사항:
  - B팀 답변 대기 중 (자료/응답 대기) [확인 필요]
  - 마감: 금요일 — 지연 시 후속 일정 영향 가능
```

### 예시 2 — 충돌 기록이 있는 인수인계/토스

입력(단서):
> "이 업무 누구한테 토스할지 정리해야 해요. 메모에는 거의 끝났다고 적혀 있고, 메일 스레드에는 아직 검토 중이라고 왔어요."

출력(카드):
```
## OO 업무 토스·인계 정리 — 토스·인계 대상 업무
- 현재 상태: 확인 필요 (기록 충돌) [확인 필요]
  - 메모: "거의 끝남" / 메일 스레드: "아직 검토 중" — 어느 쪽이 최신/정확한지 확인 필요
- 첫 행동: 담당자에게 현재 상태 확인 후 토스 대상 정리
  - (근거): 메모와 메일 상태가 충돌하므로, 확정 전에 최신 상태를 먼저 확인
- 주의사항:
  - 충돌: 메모 vs 메일 (둘 다 표시, 하나로 덮지 않음)
  - 토스 전 확인 포인트: 실제 완료 범위, 남은 검토 항목, 담당자
```

## 예외/실패 대응

- 재개할 업무/프로젝트를 이어갈 단서가 거의 없으면:
  - "어느 업무/프로젝트를 이어서 할 건지, 최근 한 줄 메모, 붙여넣은 기록, 키워드나 태그 중 편한 걸 알려주시면 그 기준으로 다시 잡아드릴게요."
  - 프로젝트명/업무명, 마지막 현황 한 줄, 붙여넣은 메모·회의·메일 텍스트, 키워드/태그 등을 예시로 안내한다.
- 기록이 거의 없거나 연결 가능한 기록이 없으면:
  - "확인 가능한 기록이 거의 없어요. 최근 메모·회의·메일 중 기억나는 키워드나 태그라도 알려주시면 다시 잡아볼게요."
- 기록이 흩어져 있고 충돌하면: 하나로 정리하지 말고 충돌 그대로 출력 + "어느 쪽이 맞는지 확인 필요" 표시.
- 업무 종류 구분이 애매하면: 가장 가까운 유형으로 임시 분류하고 "(분류 확인 필요)"를 붙인다.
- 현재 상태 판정이 애매하면: 가장 가까운 상태로 두고 "(판정 확인 필요)"를 붙인다.
- 입력에 민감 정보(주민등록번호 등)가 섞여 있으면: 카드에 출력하지 않고 필요한 업무 맥락만 남긴다.
- 첫 행동을 제시할 때는 **가능하면 근거(출처/관련 기록)**를 함께 표시한다.
  - 가능하면 핵심 근거 1줄을 먼저 보여주고, 필요 시 상세 근거를 함께 표시한다.

## 현재 상태 요약 규칙 (재확인용)

- 카드 출력은 **되묻는 질문 없이 바로** 한다.
- 매 업무 카드는 **같은 순서, 같은 제목**으로 출력한다: 현재 상태 → 첫 행동 → 주의사항.
- 첫 행동/상태 판정 시 **가능하면 근거(출처/관련 기록)**를 함께 표시한다.
  - 가능하면 **핵심 근거 1줄** 먼저 보여주고, 필요하면 **상세 근거(참고/기록·출처)**를 함께 표시한다.
- 단순 할 일은 **필수 3가지만**으로 간소화하되, 현재 상태 → 첫 행동 → 주의사항의 골격은 유지한다.
- 현재 상태는 **진행 중 / 대기 중 / 완료 / 확인 필요** 기준으로 판정하되, 자료 대기 중이면 **대기 중**으로 둔다.
- **민감 정보(주민등록번호 등)는 출력하지 않는다.** 업무상 필요한 개인 특정 정보는 필요한 범위에서만 활용한다.
- 사용자가 재개 맥락(프로젝트명, 업무 종류, 단서, 키워드/태그, 붙여넣은 기록 등)을 주거나,
  서비스가 연결된 도구·MCP(메일·캘린더·메모 등)를 통해 관련 업무 자료를 찾은 경우, 그 범위에서 기록을 살핀다.
  외부 데이터를 활용하는 경우 저작권·출처 표기를 지키고, 타인 저작물·동의 없는 개인정보는 포함하지 않는다.
- 연결이 없는 경우에도 사용자가 직접 제공한 메모·요약·키워드·태그 기반으로 동작할 수 있다.
- 태그/키워드는 선택 옵션으로, 관련 업무를 찾기 쉽게 하는 보조 수단으로 활용한다.
- 여러 업무가 함께 보이면 업무별로 나누어 각각 카드를 만든다.
  - 재개 맥락과 관련도가 높은 업무를 우선한다. 기본 상한은 주요 카드 5장 정도로 두고, 이를 넘는 업무는 요약·목록으로 안내한다. 정확한 상한·화면 구성은 서비스 MVP에서 조정할 수 있다.
  - 요약·목록 안내는 카드화할 업무가 상한을 넘거나 그 외 업무가 명확히 남는 경우에 붙이며, 적은 수의 단순 입력에서는 굳이 붙이지 않는다.
  - 업무 구분이 애매하거나 하나로 묶는 것이 더 명확한 경우에는 무리하게 쪼개지 말고, 관련 업무들을 묶어 요약 카드 또는 통합 안내로 제시한다.

## 향후 확장 방향 (참고)

아래 방향은 이 스킬의 핵심 기능(업무 재개 카드)을 그대로 둔 채, 결선 MVP나 실제 서비스화 단계에서 덧붙일 수 있는 확장 아이디어다.
현재는 단일 기능 중심인 '업무 재개 카드'에 집중한다.

### MVP 범위(우선)
- **업무 재개 카드 생성**: 상태 판정 → 첫 행동 → 주의사항 카드를 매 업무별로 출력
- **재개 맥락 입력**: 프로젝트명/업무명, 최근 한 줄 메모, 붙여넣은 기록(메모·회의·메일·메신저 텍스트), 키워드/태그 등
- **도구·MCP 연동 시 관련 업무 자료 찾기**: 서비스가 연결된 메일·캘린더·메모 등MCP를 통해 관련 자료를 찾아 카드에 반영(해당 연동이 가능한 경우)
- **태그/키워드 선택 옵션**: 업무에 태그/키워드를 붙여 두면 관련 업무 찾기가 쉬워짐(필수 아님)

### 이후 확장 후보
- 실제 저장소(파일/메일/메신저/투두 도구 등)와 연결해 기록을 자동으로 끌어오기
- 업무별·날짜별 재개 카드 히스토리를 쌓아 누적 관리
- 교대근무·인수인계용 템플릿/양식 전환 기능
- "누구한테 토스" 상황에 맞는 인계용 요약 포맷 별도 제공

### MVP와 이후 확장 구분 원칙
- MVP는 **업무 재개 카드 생성**이라는 핵심 기능에 최우선 집중한다.
- MCP 연동, 태그/키워드, 내부 대화/기록 참고는 해당 기능이 실제로 가능한 범위에서만 반영한다.
- 외부 데이터를 활용하는 경우 저작권·출처 표기를 지키고, 타인 저작물·동의 없는 개인정보는 포함하지 않는다.
- 외부 기록이 없을 때는 사용자가 직접 제공한 메모·요약·키워드·태그 기반 동작을 기본으로 둘 수 있다.
- 서비스 환경에서 저장된 대화/기록을 참고할 수 있는 경우에는 그 범위에서만 참고하며,
  존재 여부·접근 권한·개인정보 포함 여부는 실제 환경에 따라 확인이 필요하다.
